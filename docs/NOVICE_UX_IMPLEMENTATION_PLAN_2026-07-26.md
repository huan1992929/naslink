# NASLink 非 IT 用户体验改进完整实施计划

日期：2026-07-26  
目标版本：`0.4.0`  
当前基线：`0.3.0-rc19`

## 一、实施结论

本次改造不重写 NASLink 的 DSM 适配、身份源、匹配、同步、OIDC 和 License 核心。

实施重点是增加一层面向普通客户的产品编排：

```text
现有能力
DSM 盘点 / 身份源 / 匹配 / 同步计划 / 写后复核 / OIDC / License
                              ↓
新增产品编排层
就绪状态 / 首次向导 / 批量业务操作 / 待办中心 / 通俗错误恢复
                              ↓
客户界面
首页 / 员工与部门 / 待处理 / 设置
```

最终目标：

> 客户公司中拥有必要管理权限、但不懂 DSM API、OIDC 和开放平台接口的员工，不看开发文档也能完成首次开通，并在日常运行中只处理系统无法安全自动决定的事项。

## 二、必须先确定的产品决策

### 2.1 首次配置与日常使用分离

- 未完成配置：只显示首次配置向导。
- 已完成配置：进入日常管理界面。
- 高级技术页面不再作为一级菜单。
- 配置中断后，重新进入时从未完成步骤继续。

### 2.2 账号同步与 Drive 免登录解耦

- 账号同步完成后即可投入使用。
- Drive OIDC 可以当场配置，也可以稍后配置。
- Drive 未配置不能阻塞员工同步。
- 首页分别显示“员工同步”和“Drive 免登录”健康状态。

### 2.3 保留现有安全边界

- 写入前必须生成计划。
- 执行前重新读取 DSM，防止计划过期。
- 写入后读取用户和群组，只有目标状态一致才算成功。
- 不提供自动删除用户或文件的动作。
- 单个冲突用户不得阻塞其他员工同步。
- 管理员、服务账号和保护账号继续禁止自动处理。

### 2.4 普通界面不展示技术协议

以下内容只放在“高级设置”或“诊断详情”：

- DSM API 名称和版本；
- HTTP 状态码；
- OIDC、Issuer、JWKS、ID Token；
- Redirect URI；
- Token、回调验签；
- UAT 前缀；
- 匹配分数和算法明细。

## 四、实施前基础治理

### 4.1 版本控制

当前工作目录不是 Git 仓库。正式开发前必须：

1. 建立由产品方控制的私有 Git 仓库。
2. 将 `main` 设置为保护分支。
3. 合并必须经过审核和自动测试。
4. 正式 SPK 只由产品方流水线构建。
5. License 私钥、发布签名和客户配置不得进入仓库。

### 4.2 文件和秘密清理

提交源码前建立允许清单，明确排除：

- `secrets.key`；
- 真实 `config.json`、`state.json`；
- OIDC 私钥；
- License 私钥；
- DSM、钉钉、企业微信真实凭据；
- 客户通讯录和真实用户数据；
- 本地构建缓存和临时审核数据。

### 4.3 基线冻结

保存以下基线：

- 当前 `0.3.0-rc19` SPK；
- SHA-256；
- 当前源码快照；
- `go test -race ./...` 结果；
- DS920+ 当前配置备份；
- 现有 `config.json`、`state.json` 脱敏结构样例；
- 当前实机验收记录。

## 五、后端设计

### 5.1 就绪状态模型

新增统一返回模型：

```go
type Readiness struct {
    Mode       string          `json:"mode"`        // onboarding | daily
    NextAction NextAction      `json:"next_action"`
    Steps      []ReadinessStep `json:"steps"`
    Health     []HealthItem    `json:"health"`
    Pending    []PendingTask   `json:"pending"`
}

type ReadinessStep struct {
    ID        string `json:"id"`
    Status    string `json:"status"` // pending | blocked | ready | skipped
    Title     string `json:"title"`
    Summary   string `json:"summary"`
    Action    string `json:"action"`
}
```

新增接口：

```http
GET /api/v1/readiness
```

该接口根据真实数据计算，而不是完全依赖前端：

- DSM 是否最近验证成功；
- 身份源凭据和权限是否通过；
- 是否存在通讯录快照；
- 是否选择部门范围；
- 范围内账号是否全部确认或安全跳过；
- 是否已启用同步；
- Drive 是否配置并测试；
- License 是否有效；
- 是否存在失败同步或冲突。

### 5.2 持久化配置进度

在 `state.Data` 中增加：

```go
type Onboarding struct {
    Version          int       `json:"version"`
    CurrentStep      string    `json:"current_step"`
    StartedAt        time.Time `json:"started_at,omitempty"`
    CompletedAt      time.Time `json:"completed_at,omitempty"`
    DriveDeferred    bool      `json:"drive_deferred"`
    ScopeMode        string    `json:"scope_mode"` // all_active | selected
    DSMVerifiedAt    time.Time `json:"dsm_verified_at,omitempty"`
    IdentityVerifiedAt time.Time `json:"identity_verified_at,omitempty"`
    DriveVerifiedAt  time.Time `json:"drive_verified_at,omitempty"`
}
```

原则：

- “是否可继续”由真实状态计算。
- `CurrentStep` 只用于恢复用户位置。
- 外部连接健康不能因为曾经成功就永久显示正常。
- 旧版没有该字段时自动填充默认值，不阻止启动。

### 5.3 一站式 DSM 接口

新增：

```http
POST /api/v1/onboarding/dsm/connect
```

输入：

- 管理账号；
- 密码；
- 可选高级地址和证书策略。

一次完成：

1. 保存加密凭据；
2. DSM 会话登录；
3. API 能力检测；
4. 用户与群组只读盘点；
5. DSM 版本、型号和 Drive Server 检测；
6. 写入最近成功时间；
7. 返回通俗结果。

失败响应采用稳定错误类型：

```json
{
  "code": "dsm_auth_failed",
  "title": "无法登录这台群晖",
  "impact": "NASLink 尚未读取或修改任何账号",
  "next_action": "检查管理员账号和密码后重新连接",
  "technical_detail": "..."
}
```

### 5.4 一站式身份源接口

新增：

```http
POST /api/v1/onboarding/identity/connect
```

一次完成：

1. 保存身份源和应用凭据；
2. 验证 Token；
3. 检测部门和员工读取权限；
4. 检测可见范围；
5. 检测匹配字段；
6. 检测事件接入状态；
7. 权限通过时自动拉取通讯录；
8. 返回缺失权限和开通指引 ID。

钉钉、企业微信返回同一结构，前端不处理平台差异。

### 5.5 部门范围批量接口

新增：

```http
PUT /api/v1/onboarding/scope
```

支持：

```json
{
  "mode": "all_active",
  "department_ids": []
}
```

或：

```json
{
  "mode": "selected",
  "department_ids": ["1", "12", "13"]
}
```

后端统一完成：

- 选择部门；
- 生成稳定 DSM 群组名；
- 保留已有部门映射；
- 返回在职、离职、排除和冲突人数。

### 5.6 匹配结果业务分组

保留现有 `Match.Score` 和 `Reasons`，但新增面向产品的派生分类：

```text
existing_confirmed
needs_review
will_create
protected_or_conflict
```

新增：

```http
POST /api/v1/onboarding/matches/accept-safe
```

只批量确认：

- 邮箱或工号确定性一致；
- 唯一候选；
- 非保护账号；
- 未被其他员工占用。

冲突和共用账号永远不批量确认。

### 5.7 首次同步启用接口

新增：

```http
POST /api/v1/onboarding/sync/enable
```

输入：

- NASLink 管理密码；
- 默认自动化策略；
- 当前预览计划 ID。

后端必须：

1. 再次验证管理员密码；
2. 检查计划是否仍为最新；
3. 重新读取 DSM；
4. 重建差异；
5. 如差异变化，拒绝执行并返回新预览；
6. 执行；
7. 写后复核；
8. 只在全部关键检查完成后标记同步已启用。

保留旧确认词接口供高级/UAT 使用，普通向导不展示。

### 5.8 Drive 免登录状态

新增：

```http
GET  /api/v1/drive/readiness
POST /api/v1/drive/preflight
POST /api/v1/drive/test/start
GET  /api/v1/drive/test/{id}
```

检测项：

- Issuer 为可访问 HTTPS；
- discovery 和 JWKS 可读取；
- DSM Client ID 和 Redirect URI 完整；
- Drive Server 已安装；
- 当前测试用户有固定绑定且在职；
- 启动票据和 OIDC 回调成功；
- 最终进入 Drive Web。

浏览器端真实跳转无法完全由服务端代替，因此测试状态需要记录开始、回调、签发和最终确认。

### 5.9 待处理事项

不新增复杂工单系统，第一版从现有状态派生：

- 未确认匹配；
- 保护账号冲突；
- 同步失败；
- 写后复核失败；
- 身份源权限失效；
- DSM 不可连接；
- Drive 测试失败；
- License 临期或异常；
- 离职文件交接提醒。

接口：

```http
GET /api/v1/tasks
```

每项统一返回：

```json
{
  "id": "match:user-123",
  "severity": "warning",
  "title": "张三需要确认原有账号",
  "impact": "在确认前不会创建或修改张三的群晖账号",
  "recommended_action": "从两个候选账号中选择一个",
  "action_type": "review_match",
  "action_target": "user-123"
}
```

### 5.10 脱敏诊断包

新增：

```http
GET /api/v1/support/diagnostics
```

只能包含：

- 产品版本；
- DSM 版本和能力名称；
- 连接状态；
- 身份源类型和权限结果；
- 数据数量；
- 最近错误类型；
- 同步计划 ID 和状态；
- License 状态。

必须排除：

- 密码和 Secret；
- Token；
- 员工姓名、手机号、邮箱；
- DSM 用户名；
- 外网域名中的客户标识；
- License 激活码。

## 六、前端信息架构

### 6.1 首次配置模式

向导共八个状态：

1. 欢迎和准备条件；
2. 连接群晖；
3. 连接企业通讯录；
4. 选择同步人员；
5. 确认已有账号；
6. 预览并启用同步；
7. 可选 Drive 免登录；
8. 完成。

布局规则：

- 页面顶部显示步骤和完成进度。
- 每页只有一个主按钮。
- 次要操作使用文字按钮。
- 每步支持保存退出。
- 返回时不丢失已完成状态。
- 不满足前置条件时说明原因，不显示空表。
- 高级设置默认折叠。

### 6.2 日常管理模式

一级导航：

```text
首页
员工与部门
待处理
设置
```

原页面迁移关系：

| 原页面 | 新位置 |
|---|---|
| 总览 | 首页 |
| 连接配置 | 设置 > 系统连接 |
| DSM 盘点 | 设置 > 高级 > 群晖账号检查 |
| 组织同步 | 员工与部门 > 同步范围 |
| 账号匹配 | 员工与部门 > 账号详情；冲突进入待处理 |
| 同步中心 | 首页和待处理；运行记录放设置或详情 |
| 系统授权 | 设置 > 授权与版本 |

### 6.3 首页状态

正常状态：

```text
系统运行正常，无需处理
上次同步：今天 09:30
员工：286
下次检查：今天 10:30
Drive 免登录：正常
```

异常状态只突出一个最高优先级事项，并提供一个主按钮。

### 6.4 员工与部门

主表字段：

- 姓名；
- 部门；
- 在职状态；
- 群晖账号；
- 同步结果；
- Drive 状态。

以下字段进入抽屉详情：

- 平台 Subject；
- DSM UID；
- 匹配分数；
- 匹配原因；
- 所属全部群组；
- 最近同步记录。

### 6.5 空状态

所有空状态必须回答：

1. 为什么没有数据；
2. 是否影响现有账号；
3. 下一步做什么。

零数据时隐藏：

- 分页；
- 筛选；
- 批量操作；
- 空白表头；
- 无意义统计。

### 6.6 错误信息

统一三段式：

```text
发生了什么
有什么影响
现在怎么处理
```

技术详情默认折叠，可复制给服务人员。

## 十二、发布和回滚

### 12.1 版本节奏

```text
0.4.0-alpha1  本地向导和状态迁移
0.4.0-beta1   DS920+ 新安装和升级
0.4.0-rc1     钉钉端到端
0.4.0-rc2     企业微信和 Drive
0.4.0         首批客户交付
```

### 12.2 升级策略

升级前：

- 自动备份配置和状态；
- 验证备份可读取；
- 记录当前版本；
- 检查磁盘空间。

升级后：

- 运行配置迁移；
- 启动只读健康检查；
- 不自动执行同步；
- 管理员确认后恢复定时任务。

### 12.3 回滚策略

如果 `0.4.0` 启动或迁移失败：

- 停止新版本；
- 恢复升级前备份；
- 安装 rc19 回滚包；
- 禁用自动同步；
- 保留失败诊断；
- 不对 DSM 执行补偿性删除。

## 十三、主要风险和控制

| 风险 | 控制措施 |
|---|---|
| DSM 内部 API 版本变化 | 版本探测、熔断、只读预检、写后复核 |
| 客户误填管理员凭据 | 一站式检测、通俗错误、凭据加密 |
| 钉钉/企微权限不足 | 分项检测、缺项指引、重新检查 |
| 旧配置升级丢失 | 版本迁移测试、升级前备份、回滚 |
| 自动同步误改 | 保护账号、计划重读、动作白名单 |
| 离职动作影响业务 | 只禁用访问、不删除文件、记录审计 |
| 单个冲突阻塞全局 | 按员工隔离，其他员工继续 |
| OIDC 配置过于复杂 | 与同步解耦、分步助手、真实登录测试 |
| 诊断泄密 | 服务端字段允许清单和自动脱敏测试 |
| 合作开发失控 | 私有仓库、保护分支、产品方签名和发布 |

## 十五、完成定义

只有同时满足以下条件，才可以称为“普通客户可交付版”：

- 新安装默认进入首次向导；

- 一个冲突不阻塞全局；
- 同步前预览、执行前重读、写后复核；
- 没有自动删除用户或文件；
- rc19 可无损升级；
- DS920+ 实机流程通过；
- 钉钉和企业微信真实权限通过；
- Drive 真实免登录通过；
- 非 IT 测试人员独立完成验收任务；
- 可以安全回滚。

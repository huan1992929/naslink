# NASLink 产品复核报告（2026-07-17）

## 结论

NASLink 已经不是概念 Demo，而是一个可安装、可配置、可签发授权的 **0.3.0-rc2 二期商品版候选**。本地代码、自动测试、SPK 构建、独立授权中心和在线激活闭环均已跑通；rc2 新增企业微信自建应用进入 Synology Drive Web 的静默免登链路。

当前还不能定义为“客户正式交付版”。决定是否可售的最后门槛不是继续堆功能，而是在 DS920+ / DSM 7.2、真实钉钉或企业微信租户、Synology Drive Web 上完成端到端验收。

## P0：正式交付前必须完成

1. 在 DS920+ / DSM 7.2 手动安装、启动、重启、升级和卸载 SPK。
2. 校准 `SYNO.Core.User`、用户群组和账号状态写入参数，完成测试前缀账号的创建、禁用、恢复和群组变更。
3. 用真实钉钉测试企业验证 OAuth、通讯录、Stream 人员事件；再用企业微信验证回调验签、解密和通讯录事件。
4. 配置 DSM OIDC Client，验证已绑定员工进入 Synology Drive Web，离职和未绑定员工被拒绝。
5. 完成一次人员“入职、调岗、离职、重新入职”的全链路演练，并核对原有 Home、Drive 文件与权限不受损。

## P1：试点客户前建议修正

1. **密码自动填充风险**：本轮初始化后，浏览器将 NASLink 管理密码自动填入 DSM 密码框。虽然没有自动保存，但存在管理员误点“保存加密配置”的风险。应给外部系统 Secret 使用明确的 `autocomplete="new-password"` 或分离凭据表单，并在载入配置时强制清空。
2. **页面切换不归顶**：从长页面切换到“系统授权”时保留原滚动位置，导致页面标题和主操作被裁掉。导航切换后应滚动到内容顶部并恢复焦点。
3. 钉钉 Stream 配置变更后需要重启套件，管理页面应显示明确提示和连接状态。
4. 高风险“人员变动事件自动执行”只有复选框提示，应增加二次确认、影响范围摘要和建议灰度步骤。
5. `dist/` 同时保留 0.1、0.2、0.3 三个 SPK，正式交付目录应只保留当前版，避免客户装错。

## P2：规模销售前补齐

1. 独立授权中心目前适合早期交付，但仍是单机文件存储；规模销售前增加数据库、自动备份、恢复演练、管理员角色和登录审计。
2. 增加同步失败的钉钉/企业微信通知，不只依赖管理员主动打开后台。
3. 增加 SPK 在线/离线升级、失败回滚和兼容矩阵。
4. 准备 Synology 套件签名或清晰的第三方套件安装说明。
5. 如果后续需要同一客户同时使用钉钉和企业微信，应另立多身份源合并规则；当前版本是一企一主身份源。

- **完成 P0**：首批付费试点版。

- **完成 P2**：渠道与规模交付版。

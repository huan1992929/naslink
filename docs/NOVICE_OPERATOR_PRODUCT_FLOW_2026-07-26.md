# NASLink 非 IT 员工产品流程设计（2026-07-26）

## 目标

目标使用者不是实施工程师，而是客户公司里拥有必要管理权限、但不理解 DSM API、OIDC、OAuth 和通讯录接口的行政、办公室或综合管理人员。

产品要达到：

> 用户只需要回答业务问题、复制必要信息、确认系统建议；不需要理解内部技术架构，也不需要记住各页面之间的依赖关系。

需要承认一个现实边界：NASLink 不能绕过钉钉、企业微信和 DSM 的管理员授权。客户仍然要有权创建企业应用、开放通讯录权限并配置 DSM SSO，但产品可以把这些动作变成逐步教程、自动检测和明确的修复提示。

## 当前流程的问题

![当前首次启动](../output/audit/2026-07-26-novice-flow/01-current-first-run.png)

首次启动只设置 NASLink 密码，完成后直接暴露七个技术菜单。

![当前系统首页](../output/audit/2026-07-26-novice-flow/02-current-dashboard.png)

首页展示用户数、群组数和 OIDC 链路，但没有告诉首次使用者下一步做什么。

![当前同步工作台](../output/audit/2026-07-26-novice-flow/03-current-sync-workbench.png)

同步工作台已经具备正确的依赖顺序，但它应该成为首次配置主流程，而不是第六个功能页面。

![当前连接配置](../output/audit/2026-07-26-novice-flow/04-current-connection.png)

连接页面同时暴露 DSM、证书、测试前缀、AppKey、API 地址和事件令牌，超过非 IT 用户一次能够理解的范围。

![当前权限检测](../output/audit/2026-07-26-novice-flow/05-current-permission-check.png)

权限检测机制是正确基础，下一步应把检测结果直接转化为处理步骤，而不是让用户自己阅读接口状态。

## 新的产品总流程

```mermaid
flowchart LR
    A["欢迎并检查准备条件"] --> B["连接这台群晖"]
    B --> C["连接钉钉或企业微信"]
    C --> D["选择同步人员"]
    D --> E["确认已有账号"]
    E --> F["预览并启用账号同步"]
    F --> G["可选：配置 Drive 免登录"]
    G --> H["完成并进入日常首页"]
```

关键调整：

1. 首次登录只进入配置向导，不显示完整后台。
2. 账号同步先完成，Drive 免登录作为可选的后续步骤，互不阻塞。
3. 每个页面只要求用户完成一个决定。
4. 页面永远只有一个主按钮。
5. 系统自动完成读取、对比、匹配和验证，用户只做授权和确认。
6. 每一步保存状态，关闭页面后可继续。

## 首次开通流程

### 第 0 步：欢迎与准备检查

页面标题：

> 开始使用 NASLink

用户先选择：

- 使用钉钉；
- 使用企业微信。

产品随后显示一张准备清单：

- 可以登录这台群晖的管理员账号；
- 可以进入钉钉或企业微信管理后台；
- 企业已安装 Synology Drive Server；
- 如需外网扫码登录，准备企业域名和 HTTPS 地址。

页面提供两个入口：

- **我自己配置**；
- **请服务商协助**。

“请服务商协助”只生成脱敏诊断信息和本次配置编号，不上传密码、Secret 或员工数据。

### 第 1 步：连接这台群晖

页面不再要求用户理解 DSM 地址。

系统自动显示：

```text
已找到这台群晖
设备：DS920+
DSM：7.2.x
Drive Server：已安装
```

用户只填写：

- DSM 管理账号；
- DSM 密码。

主按钮：

> 授权 NASLink 检查这台群晖

点击后自动完成：

- 连接测试；
- DSM 版本识别；
- 用户和群组只读盘点；
- Drive Server 检测；
- 权限能力检测。

成功状态：

> 群晖连接成功，已读取 126 个账号和 18 个群组。本次没有修改任何内容。

高级字段隐藏在“连接有问题？”中：

- DSM 地址；
- HTTPS 端口；
- 自签名证书；
- API 兼容信息；
- UAT 安全前缀。

### 第 2 步：连接企业通讯录

页面标题：

> 连接公司的钉钉通讯录

默认只显示：

- Client ID / AppKey；
- Client Secret。

旁边提供：

- “去钉钉哪里查找”图文指引；
- 每个值对应的管理后台位置；
- 复制示例；
- “我没有权限”处理入口。

主按钮：

> 保存并检查权限

系统依次检查：

- 应用凭据；
- 部门读取权限；
- 员工读取权限；
- 应用可见范围；
- 账号匹配字段；
- 人员变动事件。

检测结果不能只写“失败”，必须写成：

> 还缺 2 项通讯录权限。NASLink 目前不能读取员工名单，也不会修改群晖。请在钉钉后台开通“部门读取”和“员工读取”。

每一个缺项提供：

- 去哪里开通；
- 要勾选哪个权限；
- 开通后“重新检查”。

全部通过后自动拉取通讯录，不要求用户再去另一个页面点击“拉取”。

### 第 3 步：选择需要同步的人员

页面首先提供两个业务选项：

- **同步全部在职员工（推荐）**；
- **只同步指定部门**。

选择指定部门时再展开部门树、搜索和人数统计。

页面持续显示影响范围：

```text
已选择 12 个部门
包含 286 名在职员工
排除 7 名离职或停用员工
```

这一阶段只保存范围，不修改 DSM。

主按钮：

> 使用这个人员范围

### 第 4 步：确认已有账号

不再向普通用户强调匹配分数和算法，把结果分成四类：

| 业务分组 | 用户看到的解释 | 默认处理 |
|---|---|---|
| 已找到原账号 | 邮箱或工号一致，将保留原文件和权限 | 自动确认 |
| 需要你确认 | 找到多个可能账号 | 必须人工选择 |
| 将创建新账号 | DSM 没有对应账号 | 按规则新建 |
| 暂不处理 | 共用账号、管理员账号或高风险冲突 | 不写入 |

页面顶部显示：

```text
268 人可按建议处理
11 人需要确认
7 人暂不处理
```

主按钮：

> 接受安全建议并继续

只有“需要你确认”的员工必须逐条处理。确认时用户只回答：

> 张三原来使用哪个群晖账号？

而不是让用户理解“绑定映射”“置信度”或“评分规则”。

### 第 5 步：预览并启用账号同步

页面显示第一次执行的业务摘要：

```text
绑定已有账号：253
创建新账号：15
调整部门群组：36
禁用账号：0
删除账号或文件：0
```

默认同步策略：

- 新员工：自动创建账号；
- 调岗：自动调整部门群组；
- 离职：立即停止 SSO，并禁用对应 DSM 账号；
- 冲突：暂停该员工，通知管理员；
- 删除：永远不自动执行。

启用时不要求输入开发式确认词，改为再次输入 NASLink 管理密码。

主按钮：

> 确认并启用员工同步

成功后显示写入复核：

> 员工同步已启用。15 个账号创建成功，36 项群组调整已复核，0 项失败。

### 第 6 步：可选配置 Drive 免登录

账号同步完成后，产品询问：

> 是否让员工从钉钉或企业微信直接进入 Synology Drive？

按钮：

- **现在配置**；
- **稍后配置**。

选择稍后配置不会影响账号同步。

选择现在配置后进入分步助手：

1. NASLink 生成 DSM 所需参数；
2. 用户点击复制；
3. 页面用截图标明粘贴到 DSM 的具体字段；
4. 从 DSM 复制回调地址；
5. NASLink 自动检查配置；
6. 用当前账号完成一次 Drive 测试登录。

普通页面只使用“Drive 免登录”，以下术语放进“技术详情”：

- OIDC；
- Issuer；
- Well-known；
- ID Token；
- Redirect URI。

成功状态：

> Drive 免登录测试成功。员工可以从企业工作台直接进入 Synology Drive。

### 第 7 步：完成

完成页面只显示客户关心的结果：

```text
群晖：连接正常
钉钉通讯录：286 名员工
员工同步：已启用
需要人工处理：0
Drive 免登录：已通过测试
```

主按钮：

> 进入 NASLink 首页

## 日常使用流程

首次配置完成后，不再显示七个技术菜单。一级导航收敛为：

1. **首页**
2. **员工与部门**
3. **待处理**
4. **设置**

### 首页

正常时只显示：

> 系统运行正常，无需处理。

附带：

- 上次同步时间；
- 同步员工数量；
- 下一次自动检查；
- Drive 免登录状态。

异常时首页只把最重要的一件事放在最前面：

> 钉钉通讯录权限已失效。员工变动暂时不会同步，群晖现有账号不会受影响。

主按钮：

> 重新连接钉钉

### 员工与部门

用户从员工视角查看：

- 姓名；
- 部门；
- 在职状态；
- 群晖账号；
- 同步结果；
- Drive 访问状态。

DSM 用户、群组、绑定表和匹配分数作为详情，不作为主表结构。

### 待处理

只出现系统无法安全自动决定的事项：

- 同名或多个历史账号；
- 共用账号；
- 管理员账号；
- 离职文件交接；
- 同步失败；
- 身份源权限失效。

每条待办只给出：

- 发生了什么；
- 会造成什么影响；
- 推荐怎么处理；
- 一个主操作。

### 设置

包含：

- 群晖连接；
- 钉钉或企业微信；
- Drive 免登录；
- 自动同步策略；
- 授权与版本；
- 高级设置。

DSM API、OIDC 参数和 UAT 测试入口只在高级设置内出现。

## 人员变动的默认自动流程

### 新员工入职

```text
通讯录新增员工
→ 自动检查历史账号
→ 无冲突则创建或绑定
→ 加入部门群组
→ 写入后复核
→ 首页显示成功记录
```

普通管理员无需操作。

### 员工调岗

```text
部门发生变化
→ 计算新旧群组差异
→ 加入新部门群组
→ 按策略移出旧部门群组
→ 写入后复核
```

如果涉及受保护群组，转为待处理事项。

### 员工离职

```text
员工变为离职
→ 立即阻止企业身份登录
→ 禁用对应 DSM 账号
→ 保留文件
→ 生成文件交接待办
```

系统不删除账号和文件。

### 同名或账号冲突

```text
发现多个可能账号
→ 暂停该员工的写入
→ 其他员工继续同步
→ 待处理中心要求管理员选择
```

一个冲突不能阻塞全公司的正常同步。

## 错误信息规范

所有错误都使用三句话：

1. **发生了什么**；
2. **对业务有什么影响**；
3. **现在应该做什么**。

示例：

> NASLink 暂时无法连接群晖。今天的人员变动已安全保留，没有写入或删除任何账号。请检查群晖是否开机，然后点击“重新检查”。

禁止普通页面直接显示：

- DSM 错误码；
- HTTP 状态码；
- API 方法名；
- Token；
- 回调验签；
- OIDC 协议错误。

技术细节放在“查看诊断信息”中，供服务人员使用。

## 系统自动做什么，客户必须做什么

### 系统可以自动完成

- 识别本机 DSM 地址和版本；
- 检测 Drive Server；
- 读取 DSM 用户与群组；
- 检查身份源权限；
- 拉取通讯录；
- 计算部门范围；
- 匹配历史账号；
- 生成同步计划；
- 执行后复核；
- 监控人员变动和异常。

### 客户无法完全免掉的动作

- 提供 DSM 管理权限；
- 在钉钉或企业微信创建/授权企业应用；
- 开通通讯录权限和应用可见范围；
- 在 DSM 中登记 Drive SSO 客户端；
- 确认存在歧义的历史账号。

产品的责任不是假装这些动作不存在，而是让客户准确知道去哪里、填什么、是否成功，以及失败后下一步是什么。

## 交付判断

把上述流程落地后，客户公司的非 IT 员工可以完成：

- 首次连接；
- 选择人员范围；
- 确认历史账号；
- 启用自动同步；
- 在指导下配置 Drive 免登录；
- 处理少量冲突和错误。

真正的产品成功标准不是“七个页面都能打开”，而是：

> 用户不看开发文档，也能从第一步走到“系统运行正常”，并且遇到失败时知道下一步点哪里。

# 钉钉企业内部应用开通与 NASLink 检测指南

NASLink 不能代替企业管理员在钉钉后台同意通讯录权限。产品会把必须的人工步骤集中成一次配置，并通过只读检测告诉管理员当前缺少什么、应用实际能看到多少部门和员工。

## 1. 创建企业内部应用

1. 使用企业管理员账号进入[钉钉开放平台](https://open-dev.dingtalk.com/)。
2. 创建“企业内部应用”，建议命名为“企业网盘”或“NASLink 企业网盘”。
3. 在应用凭证页复制 Client ID（AppKey）和 Client Secret。
4. 将两项填写到 NASLink 的“连接配置 → 钉钉 → 应用凭据”。

Client Secret 只在保存时传给 NASLink，并在本机加密保存。页面重新打开后不会回显明文。

## 2. 申请通讯录权限

钉钉控制台的权限名称可能随版本调整，应以控制台搜索结果为准。

当前 NASLink 通讯录接口必须开通：

- 通讯录部门信息读权限 `qyapi_get_department_list`：用于读取部门树并建立 DSM 部门群组。
- 通讯录部门成员读权限 `qyapi_get_department_member`：用于按部门读取员工、在职状态和所属部门。

建议开通：

- 员工工号：接口可返回时优先用于匹配客户已有 DSM 账号。
- 邮箱等个人信息 `fieldEmail`：用于精确匹配已有账号。
- 企业员工手机号信息 `fieldMobile`：仅在客户允许的情况下作为冲突辅助判断；NASLink 页面会按敏感字段策略展示。

NASLink 不需要通讯录写权限，不会修改钉钉员工或部门。

## 3. 设置应用可见范围

可见范围决定 NASLink 最终能同步哪些人。建议只勾选需要使用群晖或 Synology Drive 的组织范围，不必默认选择全公司。

配置后进入“连接配置 → 钉钉 → 权限检测”，核对：

- 可见部门数量；
- 可见员工数量；
- 在职员工数量；
- 工号、邮箱或手机号的可用情况。

接口调用成功但员工为 0，通常不是 NASLink 故障，而是应用可见范围为空或未包含目标部门。

## 4. 启用人员变动事件

NASLink 使用钉钉 Stream 模式建立长连接，不要求客户把群晖事件回调端口暴露到公网。请在应用的事件与回调配置中启用 Stream，并订阅：

- `user_add_org`：员工加入企业；
- `user_modify_org`：员工信息或部门变化；
- `user_leave_org`：员工离开企业；
- `org_dept_create`：新建部门；
- `org_dept_modify`：修改部门；
- `org_dept_remove`：删除部门。

“Stream 已连接”只说明 NASLink 与钉钉的通道已经建立。是否订阅了全部事件仍需管理员在钉钉后台确认，并通过一次测试人员变动验证。

## 5. 发布应用版本

如果钉钉开发者后台提示“版本发布后，当前修改才能生效”，请创建并发布一个应用版本。权限、可见范围或事件订阅调整完成但未发布时，NASLink 仍可能读取到旧配置。

## 6. 正式启用前检查

1. “应用凭据”显示验证通过。
2. “权限检测”中应用凭据、部门读取、员工读取均通过。
3. 可见部门和员工数量与计划同步范围相符。
4. 保存配置。
5. 前往“组织同步”刷新通讯录快照。
6. 选择需要受管的部门；未选择的部门不会生成同步动作。
7. 前往“账号匹配”确认历史 DSM 账号绑定。
8. 前往“同步中心”生成预览，确认后再执行。

## 常见问题

| 现象 | 常见原因 | 处理方法 |
|---|---|---|
| 无法换取 Token | Client ID、Secret 错误，或应用未启用 | 重新复制应用凭证并验证应用状态 |
| 返回无权限或错误码 60011 | 缺少部门或员工只读权限 | 回到权限管理申请对应通讯录权限 |
| 能读取部门但员工为 0 | 应用可见范围未包含员工 | 调整应用可见范围并重新检测 |
| 员工数量明显偏少 | 只勾选了部分部门，或子部门未包含 | 核对可见范围与部门树 |
| Stream 已连接但人员变动无记录 | 未订阅对应事件类型 | 核对六类人员和部门事件 |
| 有员工但账号匹配依据不足 | 工号、邮箱均为空 | 开通建议字段，或在账号匹配页人工确认 |

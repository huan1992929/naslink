# NASLink 易用性交付审核（2026-07-26）

## 审核结论

NASLink 的核心能力已经形成闭环，但当前产品仍然是“给研发和实施工程师使用的管理控制台”，还不是“普通企业管理员可以独立完成配置的交付产品”。

当前最主要的问题不是页面是否美观，也不是功能数量，而是：

> 产品把 DSM、身份源、账号匹配、同步引擎和 OIDC 等技术模块直接暴露给了用户，却没有把它们串成一条可理解、可中断后继续、出错后可恢复的任务流程。

因此，当前版本适合内部测试和工程师陪同交付，不建议直接交给不懂 DSM、OIDC、钉钉开放平台或企业微信接口的客户自行安装配置。

### 当前成熟度

| 维度 | 判断 | 说明 |
|---|---|---|
| 核心技术能力 | 良好 | 单 SPK、DSM 盘点、通讯录、匹配、同步计划、Drive SSO、授权均已有实现 |
| 数据安全边界 | 良好 | 默认只读、写入前预览、不删除账号和文件 |
| 视觉一致性 | 基本良好 | 白色工作台风格统一，表格与表单密度可接受 |
| 首次配置体验 | 较差 | 没有向导、进度、推荐下一步和断点续配 |
| 故障恢复体验 | 较差 | 空表、零数据和连接异常不能自然引导用户解决 |
| 日常管理体验 | 一般 | 缺少“待处理事项”和“系统是否健康”的统一入口 |
| 普通用户自助交付 | 暂不合格 | 用户必须理解多个技术名词和前后依赖关系 |

## 逐步体验审核

### 1. 首次启动：需要改进

![首次启动](../output/audit/2026-07-26-product-review/01-first-launch.png)

优点：

- 初始化动作简单，没有一次要求填写全部外部系统参数。
- 安全边界和管理入口清晰。

问题：

- 只要求输入一次管理密码，没有确认密码、强度反馈和“这是 NASLink 后台密码，不是 DSM 密码”的说明。
- 按钮“进入控制台”没有表达它同时完成密码设置。
- 模态框后面直接露出七个技术模块，用户还没开始就需要面对完整系统复杂度。
- 初始化完成后直接进入空仪表盘，没有进入配置向导。

建议：

- 改为“设置 NASLink 管理密码”，增加确认密码、强度和用途说明。
- 主按钮改为“设置密码并开始配置”。
- 初始化成功后直接进入首次配置向导。

### 2. 空白总览：阻碍首次使用

![空白总览](../output/audit/2026-07-26-product-review/02-empty-dashboard.png)

优点：

- 信息密度不高，视觉层次清楚。
- 能看到产品包含 DSM、身份源、账号和 Drive 登录链路。

问题：

- 没有唯一的主操作按钮，用户不知道第一步该点哪里。
- “OIDC 签发”“ID Token”等内容描述的是技术架构，不是客户想完成的工作。
- “—”和“0”只能说明没有数据，不能说明为什么没有、怎么解决。
- 没有整体配置进度、阻塞项、最近成功同步和待处理异常。

建议：

- 首次使用时，总览改成“配置进度中心”，只显示当前步骤、阻塞原因和一个推荐操作。
- 完成配置后，总览改成“运行健康中心”，显示连接健康、最近同步、待确认变更和异常。
- 用户文案改为“连接企业通讯录”“确认现有账号”“配置 Drive 免登录”。

### 3. 连接配置：信息过载

![连接配置](../output/audit/2026-07-26-product-review/03-connection-configuration.png)

优点：

- DSM 与当前身份源左右分栏，关系清楚。
- 钉钉和企业微信可以切换，不会同时堆叠全部字段。
- 密钥字段使用密码输入框。

问题：

- 一个页面同时出现 DSM 管理凭据、证书、UAT 前缀、Client ID、Secret、授权地址、API 地址和事件令牌。
- 授权地址、API 地址、UAT 前缀等高级字段对普通客户不应默认可见或可编辑。
- “保存配置”和“验证连接”是两个分散动作，用户不知道现在是“已填写”“已保存”还是“已连接”。
- 没有清楚说明每个值要去钉钉或企业微信的哪个页面取得。
- 没有把缺失权限直接转化为可执行的处理步骤。

建议：

- 首屏只保留 DSM 管理账号、密码和身份源 AppKey/Secret。
- 自动识别本机 DSM 地址；授权地址、API 地址、证书策略和 UAT 前缀收进“高级设置”。
- 一个按钮完成“保存并检测”，随后显示“已连接 / 需要处理 / 连接失败”。
- 权限检测结果旁直接提供“去哪里开通”和“重新检测”。

### 4. Drive 免登录：当前最难的交付步骤

![Drive OIDC 配置](../output/audit/2026-07-26-product-review/04-drive-oidc-configuration.png)

优点：

- OIDC 参数集中在 DSM 卡片内，没有再增加第三个页面区块。
- 参数结构完整，适合实施工程师排查问题。

问题：

- Issuer、Client ID、Client Secret、Redirect URI 和 Well-known URL 需要在 NASLink 与 DSM 之间反复复制。
- 页面只提供字段，没有表达正确的配置顺序。
- 用户不知道哪些值由 NASLink 生成、哪些值由 DSM 生成、哪些要复制到对方系统。
- 缺少一次端到端“测试 Drive 免登录”，因此填完参数也不知道是否真正成功。

建议：

- 改成分步助手：生成 NASLink 参数 → 复制到 DSM → 从 DSM 复制回调地址 → 保存 → 测试登录。
- 每个生成值增加复制按钮和“复制到 DSM 的哪个字段”说明。
- 最后必须提供“用当前管理员测试 Drive 免登录”，并输出明确结果。
- OIDC、Issuer、Well-known 等术语保留在“技术详情”，默认显示用户语言。

### 5. 组织同步空状态：看起来像系统坏了

![组织同步空状态](../output/audit/2026-07-26-product-review/05-organization-empty-state.png)

优点：

- 已经把部门范围、员工目录、离线导入分成子页。
- 有通讯录拉取入口。

问题：

- 没有数据时仍显示完整空表、过滤器和分页器，用户容易理解成拉取失败。
- 空状态没有说明是“尚未连接”“权限不足”还是“尚未拉取”。
- “拉取通讯录”和“重新计算”的差异不清楚。
- 用户还没有选择同步范围时，页面没有给出推荐策略。

建议：

- 空状态直接显示原因、前置条件和一个按钮，例如“尚未拉取钉钉通讯录，先检测权限并拉取”。
- 零数据时隐藏分页、筛选和无关工具。
- 拉取成功后再引导选择“同步全部部门”或“只同步指定部门”，默认不写入 DSM。

### 6. 账号匹配空状态：缺少依赖关系说明

![账号匹配空状态](../output/audit/2026-07-26-product-review/06-account-matching-empty-state.png)

优点：

- 匹配和人工绑定独立，符合安全要求。
- 没有直接创建或覆盖 DSM 账号。

问题：

- 用户无法从本页判断匹配为空是因为 DSM 未盘点、通讯录未拉取，还是部门范围未选择。
- “匹配分数”“高信”“匹配依据”偏工程化。
- 页面没有把结果转化为用户真正需要做的三类决定。

建议：

- 将结果改为四个清晰分组：
  - 可自动确认；
  - 需要你确认；
  - 将新建账号；
  - 存在冲突，暂不执行。
- 每个分组解释对文件和原有权限的影响。
- 缺少前置数据时，直接显示缺失步骤和“去完成”按钮。

### 7. 同步工作台：当前最接近正确产品形态

![同步工作台阻塞状态](../output/audit/2026-07-26-product-review/07-sync-workbench-blocked.png)

优点：

- 清楚呈现“通讯录 → 部门范围 → 账号匹配 → DSM 同步”的依赖顺序。
- 未满足条件时禁用执行，能避免误操作。
- 有“去处理”和状态提示，是当前最有任务导向的页面。

问题：

- 这个正确的工作流出现得太晚，用户必须先自行理解其他六个模块。
- “去处理”没有直接写明将去哪里、要完成什么。
- 同步完成后仍缺少“本次变更摘要”“失败项”和“下一次自动运行”。

建议：

- 把这套四步逻辑提升为首次配置首页，而不是第六个菜单。
- 按钮改为具体动作，例如“连接钉钉并拉取”“选择同步部门”“确认 3 个冲突账号”。
- 同步前显示创建、恢复、禁用和群组变更数量；同步后显示成功、失败及复核结果。

## 应改成怎样的产品结构

### 首次配置模式

首次登录后不要进入七个模块，而是进入可中断后继续的配置向导：

1. **连接这台群晖**：自动识别本机地址，只要求保存 DSM 管理服务账号。
2. **连接企业通讯录**：选择钉钉或企业微信，保存凭据并自动检测权限。
3. **选择同步人员**：选择全部或指定部门，预览人数。
4. **确认现有账号**：显示自动匹配、待确认、将新建和冲突。
5. **配置 Drive 免登录**：按步骤复制参数并完成一次真实登录测试。
6. **预览并启用**：展示第一次写入影响，管理员确认后开启同步。

每一步都必须有：

- 当前状态；
- 还缺什么；
- 一个主操作；
- 保存并退出；
- 返回后继续；
- 查看技术详情。

### 日常管理模式

首次配置完成后，顶部导航建议收敛为四项：

1. **首页**：系统健康、最近同步、待处理事项。
2. **待处理变更**：账号冲突、离职、失败任务和即将写入的变更。
3. **用户与部门**：通讯录、同步范围、账号绑定和 DSM 状态的统一视图。
4. **设置**：DSM、钉钉/企业微信、Drive 免登录、同步策略、License 和高级设置。

原来的“DSM 盘点”“账号匹配”“系统授权”仍可保留能力，但应降级为设置或用户管理下的子页，而不是要求客户理解的一级导航。

## 交付前优先级

### P0：普通客户交付前必须完成

1. 增加首次配置向导、进度保存和继续配置。
2. 把总览改成配置/健康中心，始终给出一个推荐下一步。
3. 为所有空状态增加原因、前置条件和直接处理按钮；零数据时隐藏无关表格工具。
4. 将 Drive OIDC 改成可复制、可验证的分步助手，并提供端到端登录测试。
5. 收起所有高级技术字段，重新组织一级导航。
6. 建立统一状态语言：已完成、需要处理、失败；不再用“—”表达关键状态。

### P1：首批客户试点前建议完成

1. 增加“待处理事项”中心和失败恢复入口。
2. 将账号匹配改为业务分组，支持批量确认并解释影响。
3. 把钉钉/企业微信权限教程嵌入检测结果，而不是只放独立文档。
4. 同步前后都提供清晰摘要和结果复核。
5. 增加一键导出脱敏诊断包，方便远程支持。

### P2：规模销售前补齐

1. 区分实施管理员、日常管理员和只读审计员。
2. 增加站内帮助、术语解释和按当前错误推荐的排查步骤。
3. 增加升级、证书、授权临期和身份源密钥失效的主动提醒。

## 可访问性审核

当前已有的正向基础：

- 子页面使用了 `tablist`、`tab` 和 `tabpanel` 语义。
- 标签支持左右方向键、Home 和 End 键切换。
- 状态消息有可读的状态区域。

仍需验证和改进：

- 弱化文字、禁用按钮和浅色边框需要做实际对比度测量。
- 零数据时仍出现完整表格、筛选和分页，会增加键盘与屏幕阅读器无效焦点。
- 首次密码弹窗需要明确错误提示、确认密码和焦点返回策略。
- 本轮没有完成屏幕阅读器、全键盘流程和 WCAG 自动化检查，因此不能宣称达到 WCAG 合规。

## 证据边界

- 本轮使用当前源码启动全新本地实例，完成了首次初始化、空白总览、连接配置、Drive OIDC、组织空状态、匹配空状态和同步阻塞态的浏览器审核。
- 当前网络无法连接此前的局域网地址 `192.168.5.2:17890`，因此没有重新验证真实 DS920+ 的现有数据和身份源权限。
- 本轮没有使用真实钉钉/企业微信凭据，没有执行 DSM 写入，也没有完成真实 Drive 回调。
- 浏览器中唯一的控制台错误来自审核时主动连接不完整的本地 DSM 模拟端点，不作为正式产品缺陷证据。
- 真实人员数据、错误恢复和端到端免登录仍需要在可连接的 DS920+ 上完成一次当前版本 UAT。

## 最终判断

NASLink 的后端与安全流程可以保留，当前不需要推倒重做。交付前最值得投入的不是继续增加接口，而是用一层“首次配置向导 + 日常待办中心”重新编排现有能力。

完成 P0 后，产品才会从“工程师能配置”跨到“普通企业管理员能独立完成并知道系统是否正常”。
